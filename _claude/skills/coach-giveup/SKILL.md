# ギブアップ

利用者がギブアップを宣言した。解答の段階に進む。

## 手順

1. `.atcoder-review/context.json` を読み、問題とファイルを確かめる。
2. `problemDir` の `review.json` の `progress.gaveUp` を `true` にする（ファイルがなければ作る）。
3. 問題文が手元になければ、スクリーンショットか要約を頼む。
4. 解法を `review.json` の項目にする（`line` は `null`、`kind` は `hint`、`hintLevel` は 3、見出しは「解法」など）。`<id>.md` に、方針、なぜ正しいか、計算量、実装の要点の順に書き、最後に完全な解答コードを置く。図が要れば `<id>.html` も使える。
5. 利用者の今のコードを活かせる所があれば、行に結び付けた項目（`kind` は `bug` など）として、どこをどう直せばよいかを書く。チャットでは、書いた項目の一覧だけを伝える。
6. 最後に、原因を4つ（知識不足／気づけなかった／実装ミス／時間不足）から1つ添える。
7. 公式の解説ページは、利用者が頼んだ時だけ開く（CLAUDE.md の「問題文の受け取り」）。
