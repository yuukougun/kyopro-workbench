# 問題文と実装を照らし合わせる

解き方のヒントではなく、「問題文の条件と実装が合っているか」だけを確かめる。

## 手順

1. `.atcoder-review/context.json` を読み、問題とファイルを確かめる。`dirty` が `true` なら保存を頼んで止まる。
2. 問題文が手元になければ、スクリーンショットか要約を頼む（atcoder.jp は自分からは開かない）。特に制約と出力形式の部分が要る。
3. `problemDir` の `last_test.json` があれば読み、どのサンプルで何が起きているかを確かめる。
4. 次の観点で、実装と問題文の食い違いを探す。
   - 制約の範囲（最大値・最小値、N=1 などの端）
   - 型（`int` のあふれ、`long long` が要る所、割り算・剰余の符号）
   - 境界（ループの範囲、配列の大きさ、0 始まりと 1 始まり）
   - 出力形式（改行・空白・`Yes`/`No` の綴り、小数の桁、mod）
   - 計算量（制約に対して間に合うか）
5. 見つけた食い違いを `review.json` の項目として書く（CLAUDE.md の「指摘の書き方」）。行を示し、`kind` は確実な誤りなら `bug`、可能性なら `risk`、`hintLevel` は 1。チャットでは、項目の ID と一言の要約だけを伝える。

解き方（どの手法を使うか）には触れない。食い違いが見つからなければ、そう伝える。
