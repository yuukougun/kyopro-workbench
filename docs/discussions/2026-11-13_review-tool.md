## 第7版からの主な変更（理由）
- 事実の修正（公式ドキュメントで確認）
  - WSL で使えないのはプラグインとファイル画面の編集で、`@` のファイル指定は使える。
  - `Edit` の禁止は `sed`・`tee`・リダイレクトにも効く。防げないのはスクリプト内のファイル操作。
  - サブフォルダの `.claude/skills/` は、そのフォルダのファイルを読むか編集するまで読み込まれない。
  - `settings.local.json` が自動で git の管理から外れるのは、Claude Code 自身が作った時だけ。
- atcoder.jp: Claude は自分からは開かず、利用者が明示した時だけ開く。テンプレートの settings.json には禁止を書かない（禁止は各自の許可で上書きできないため）。kyopro-atlas の方針・noai 指定と揃えるため。
- ライブラリの決定（0004・0005）を反映: includePaths は `lib/include`、CLAUDE.md に転送用ヘッダの読み方を書く。
- AC は利用者の申告で決める。`review.json` に進み具合（最高ヒント段階・AC・ギブアップ）を持たせ、記録の `support`・`status` の元にする。`/kp-review`・`/kp-giveup` は利用者だけが実行できるようにする。
- 指摘の ID を連番（`r1`…）にする。Claude は今の時刻を知るのに毎回承認が要るため。
- `last_test.json` は cph fork が書くのをやめ、fork はイベントを公開するだけ、書くのはレビュー拡張にする。fork とレビュー拡張の相互依存をなくすため。
- 指摘に行の内容（`anchor`）を持たせ、行のずれを検知する。
- `/record-problem` は `record_tool.py` 経由で `tools/ap.py` を呼ぶ（`ap.py` の絶対パスを `allowed-tools` に書けないため）。
- 肥大化を避けるため、スキル一覧パネルは作らず、メモタブ・過去の記録の表示・コンテストモードは後回しにする。
- install.sh は「差分を表示して飛ばす、`--force` で上書き」にし、`--link` を加える。vsix は GitHub Releases で配る。
- 記録形式 v2 の3項目（support・status・code）はすべて採用する。

## 使ってみてからの改善の議論（1回目。まだ着手しない）
利用者がフェーズ0〜5の準備と動作確認を終えた後の要望と、その答え。
- エディタの行末に指摘の文を出すのはやめる。ガターのアイコンとホバーは残す。パネルで指摘を選んだら該当行を一時的に強調する。
- パネルを Markdown のように見やすく表示する（パネルの中で描画する）。Mermaid は入れない。図など柔軟な表示が要る時は、Claude が HTML ファイルを書き、指摘のボタンから開く。
- 長い本文は指摘ごとの別ファイルに書く（短い見出しだけ JSON に書く）。行に結び付かない項目（方針のヒント・解説・別解など）も置けるようにする。
- チャットは短くし、中身はパネル（ファイル）に書く。セッションが残っていなくても見返せる。
- 解き直しのネタバレは、パネルを隠せばよいので気にしない。全ての項目を折りたためるようにする。
- 行のずれには自動で追従する。
- 未対処の件数のバッジは要らない（ガターのアイコンで十分）。
- コンパイルエラーの文は利用者が Claude に渡す（ライブラリ内のエラーなどで極端に長くなるため）。cph fork がコンパイルの成否しか出さない点は直したい（どこに出すかは要確認）。
- 指摘に種類（バグ・ヒント・改善・別解・ライブラリ化の候補など）を付ける。
- review.json に形の版は付けない（まだ試しの記録しかないので、古い形は捨ててよい）。

## 改善の議論（2回目。まだ着手しない）
- HTML はレビュー拡張がエディタのタブとして開く（VSCode には HTML を表示する標準の機能がないため）。
- HTML には決まった役割を持たせない。パネル（Markdown）で足りない時に、Claude が自由に書く「その他」。拡張に依存しない、単独で開けるファイルにする。
- パネルの表示: Markdown（見出し・箇条書き・表・C++ のコードの色分け）、数式（MathML）、囲み（`> [!NOTE]` など）、マーカー、意味の決まった数色。
- 指摘の種類: bug・risk・hint・improve・alt・library。今の severity はこれに統合する。
- 折りたたみ: 初期状態は見出しだけ表示し、本文は閉じる。
- 行のずれへの追従は Claude に任された（方式は Claude が決める）。
- コンパイルエラー: cph fork の判定パネルにエラーの文を表示する。高さの上限とスクロール、開閉の切り替え、コピーのボタンを付ける。

## 改善の議論（3回目。まだ着手しない）
- HTML は webview（パネルと同じ仕組み）でタブに表示する。ソースコードとしては開かない。
- HTML から外部への通信は禁じない（CDN のライブラリなども使ってよい）。
- エディタのホバーで指摘の文を出すのはやめる（コードの上に文字が重なるため）。エディタ上はガターのアイコンだけにし、カーソルを指摘のある行に置くと、パネルの側でその指摘を強調する。
