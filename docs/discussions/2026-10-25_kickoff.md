## cph の include 展開について

### 再帰展開されるか
- されている（`_cph/cph-fork.patch` の `src/bundler.ts`）。3段の入れ子 include で動作を確認済み。
- 探す順: include しているファイルのフォルダ → `cph.bundle.includePaths`。
- 同じファイルは1回だけ展開、循環 include も検出して止まる。`#pragma once` / include guard は除去。
- `// @impl` より下は提出コードの末尾にまとめて出力される。
- 細かい注意点（実害は小さい）:
  - `#ifdef LOCAL` 内で先に include したファイルを、後で条件外でも include すると2回展開される。
  - `/* */` ブロックコメント内の `#include "..."` も展開されてしまう。

### 使った関数・クラスだけを展開するか
- 提案: シンボル単位の削減はしない。展開はファイル単位のままにする。
  - C++ の解析（テンプレート、オーバーロード、マクロ、演算子、メンバ関数）が必要で、壊れたコードを出すと本番で致命的。
  - 未使用のコードがあっても害は小さい（AtCoder のコード長制限は 512KiB）。
- 代わりに「1ファイル1機能」で細かく分け、依存は include で表す。これでファイル単位で「使うものだけ」展開できる。
