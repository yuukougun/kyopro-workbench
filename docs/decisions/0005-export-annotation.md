# 0005 include 名は `// @export` 注釈で決める

- 日付: 2026-10-25
- 状態: 採用

## 決定
- 公開するファイルは冒頭のコメント部分に `// @export` を書く。
  - `// @export` → ファイル名がそのまま include 名（`"segtree.hpp"`）
  - `// @export ds/debug.hpp` → 指定した名前
  - 注釈なし → 公開しない（内部ヘルパー）
- ルール（生成スクリプトが検査し、違反があれば何も書き換えずにエラー）:
  - 冒頭のコメント部分以外に書いたらエラー。1ファイルにつき1つまで。
  - include 名は `.hpp` で終わる相対パス、最大3階層、`..` 禁止、重複禁止。
- 生成スクリプトは `include/` を空にして作り直す。転送用ヘッダには目印 `// @forward` と元ファイルのパスを書く。

## 理由（検討した他の案）
- フォルダ構成から include 名を機械的に決める案: 実ファイルを移動すると include 名も変わり、回答コードの書き換えが必要になる。
- 注釈なら置き場所と include 名を切り離せ、公開・非公開も明示できる。書き忘れはコンパイルエラーですぐ分かる。
- `// @export` の行は提出コードに残るが動作に影響はない。必要なら cph 側で取り除く。
