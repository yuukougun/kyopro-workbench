# 0004 include は転送用ヘッダで短く書く

- 日付: 2026-10-25
- 状態: 採用

## 背景
`#include "kp/ds/tree/segtree.hpp"` のように毎回フルパスを書くのは長く、覚えにくい。
cph のテスト実行は展開前のコードを g++ でコンパイルするので、g++ でも解決できる必要がある。

## 決定
- `include/` に転送用ヘッダ（中身は実ファイルへの `#include` 1行）を自動生成し、includePaths と `-I` をそこに向ける。
- `include/` 内も階層を分けてよい（`"segtree.hpp"` も `"ds/util.hpp"` も可）。深さは最大3階層。
- 同じ include 名を2つのファイルに割り当てることはできない。階層が違えば同じファイル名でもよい。
- ヘルパーや util の置き場所は自由（ライブラリ親フォルダの直下でも、`ds/` の中でもよい）。
- 回答コードは `include/` の転送用ヘッダだけを include する。`-I` と includePaths は `include/` だけを指定する。
- ライブラリ同士は、公開ファイルなら include 名で、非公開ファイルなら相対パスで include する。
- 生成した `include/` は git にコミットしない（clone 後や変更後にスクリプトで生成する）。

## 理由（検討した他の案）
- シンボリックリンク: リンク経由で開いたヘッダの中の相対パス include を g++ が解決できない（試作で確認）。
- includePaths と `-I` に全フォルダを並べる: フォルダを増やすたびに設定の変更が必要。
- コミットしない理由: 自動生成物なので、元ファイルの `@export` から必ず作り直せる。（当初はコミットする案だったが変更）
